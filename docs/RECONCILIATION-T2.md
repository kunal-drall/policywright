**Consequence for the T2 install flow (structural, from rows 29–34):** a
policywright rule install is one transaction invoking
`account.add_context_rule(...)`, carrying one `SorobanAuthorizationEntry`
whose credentials are the **account's own C-address** and whose `signature`
is an `AuthPayload` selecting the account's **admin rule** and carrying the
admin signer's signature over the rule-bound digest. The policy `install`
calls happen inside that invocation with no further entries.

### Signing hierarchy decision (Gate 2)

1. **Primary — wallets-kit 2.6.0 + Freighter, `Signer::Delegated(G)` model.**
   The wallet's G-account is the rule signer. Two sub-modes, both requiring the
   client to hand-build the nested `__check_auth(auth_digest)` entry:
   (i) G is the transaction source → nested entry uses `SourceAccount`
   credentials, the wallet only calls `signTransaction`; (ii) G is not the
   source → the wallet signs the nested entry with `signAuthEntry` (a standard
   preimage, which Freighter accepts). Simulation never returns the nested
   entry, so the client constructs it after fixing the outer entry's nonce and
   expiration.
2. **Fallback — local signer from `.env`** (`STELLAR_SECRET_KEY`, never
   printed), labelled "fallback" everywhere it appears. It is the only way to
   act as an `External(ed25519_verifier, pubkey)` signer (signs `auth_digest`
   directly), and it doubles as G for scripted/CI runs and for the pre-flight
   proof of the nested-entry construction. **The specific unsupported thing**
   is recorded in FACTS §8.4: wallet `signAuthEntry` signs
   `sha256(HashIdPreimage XDR)` after parsing it; OZ `External` signers need
   `sha256(signature_payload ‖ context_rule_ids XDR)`.
3. Never: MCP-driven signing or submission (rule 5). The MCP server emits
   artifacts and verifies; the signing surface is a separate CLI/UI step.

### Emitter-fix list (explicit; empty would have been a valid finding) — **closed by D2.5, rows 72–75**

- **E1 — `validUntilLedger` from a past ledger.** Emit `lifetimeLedgers`
  (relative) alongside, and emit an absolute `validUntilLedger` only when
  synthesis is given a live ledger head (`synth --ledger-head <n>` or an RPC
  read); otherwise `null`. Bump `schemaVersion` to 2 and update
  [context-rule-schema.md](context-rule-schema.md). Tests:
  `test/oz-context-rules.test.ts:219-229`.
- **E2 — signers must be emitted in the real `Signer` shape.** Accept
  `--signer delegated:G…` / `--signer external:<verifier C…>:<32-byte hex>`
  and emit `signers: [{type:"Delegated", address}]` /
  `[{type:"External", verifier, keyData}]` on every rule; refuse to emit a
  `stock:spending_limit` binding on a rule with no signers (it can never
  enforce).
- **E3 — policy addresses must be emitted, not left `null`.** Accept a
  `policyAddresses` map (`custom:FrequencyLimitPolicy` → C…,
  `stock:spending_limit` → C…) and emit them; keep `null` only when the
  caller supplies none, and say so in `notes`.
- **E4 — guard duplicate policy addresses within one rule** (map key
  collision).
- **E5 — fix the `notes` wording** about "one instance per token rule".
- Not an emitter fix, recorded for the installer: the encoding rules in the
  table above (enum → `Vec[Symbol, …]`, struct → sorted `ScMap` keyed by
  `Symbol`, `Option::None` → `Void`, i128 from decimal string).
