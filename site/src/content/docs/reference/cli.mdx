## Commands

| Command                                        | What it does                                                                                                                              |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run demo`                                 | End-to-end pipeline + dry-run self-check (offline, from the baked-in fixture; [src/demo.ts](https://github.com/kunal-drall/policywright/blob/main/src/demo.ts)). Exits non-zero if a scenario deviates. |
| `npm run cli -- synth`                         | Synthesize a spec from the baked-in fixture (or `--input <recorded.json>`) and print the summary + `spec.json` + `context-rule.json`; with `--out <dir>` write all four artefacts (incl. `FrequencyLimitPolicy.rs`) to a directory. |
| `npm run cli -- simulate`                      | Run the dry-run scenarios against the fixture's spec (or `--input <recorded.json>`) and print the permit / deny / flag report.             |
| `npm run record -- <txHash> [<txHash> ...]`    | Fetch one or more live transactions by hash and print them merged (ledger-close-time order) as ONE `RecordedTx` JSON.                      |
| `npm run record -- --from-simulation <file>`   | Ingest a saved `simulateTransaction` exchange instead of fetching hashes (`source: "simulation"`). Cannot be combined with hashes.         |
| `npm run cli -- install --artifact <context-rule.json> --account <C…>` | **Testnet only**, human-initiated. Validate the artifact against the OZ install signature, build the `add_context_rule` transactions with the account's `AuthPayload` entry and the `Delegated(G)` nested entry, simulate (recording, then enforcing), sign client-side with `STELLAR_SECRET_KEY` from the environment, submit. `--dry-run` simulates everything and submits nothing; `--out` writes the install log. Ran on testnet 2026-09-02: [install log, rule ids 1–3](https://github.com/kunal-drall/policywright/blob/main/examples/live/testnet/install-20260902T105742Z.json); flags below. |
| `npm run cli -- verify --artifact <context-rule.json> --account <C…>` | Read-only, no key: read the account's rules and policy params back and diff them against the artifact (PASS/FAIL); `--install-log` also checks `valid_until`. Committed reports: [verify.md](https://github.com/kunal-drall/policywright/blob/main/examples/live/testnet/verify.md) (rule ids 1–3), [verify-demo-…md](https://github.com/kunal-drall/policywright/blob/main/examples/live/testnet/verify-demo-20260902T153356Z.md) (ids 4–6). |
| `npm run mcp`                                  | Serve the same four operations — `record`, `synthesize`, `simulate`, `verify` — to an MCP client over stdio. No install or deploy tool ([MCP server](/reference/mcp-tools/)). |
| `npm run mcp:schemas -- --check`               | Fail if the JSON Schemas committed under `schemas/mcp/` drift from `src/mcp/schemas.ts` (run in CI; prints `schemas/mcp/ matches src/mcp/schemas.ts (9 files)`). |
| `npm run cli -- help`                          | Print usage (also `--help` / `-h` / no arguments).                                                                                         |

`npm run synth`, `npm run simulate`, and `npm run record` are direct package
scripts for the corresponding commands
([package.json](https://github.com/kunal-drall/policywright/blob/main/package.json)).

## Synthesis flags (`synth` and `simulate`)

Anything omitted keeps its default.

| Flag                        | Default         | Meaning                                                        |
| --------------------------- | --------------- | -------------------------------------------------------------- |
| `--input <recorded.json>`   | baked-in fixture | Synthesize (and, for `simulate`, dry-run) from a saved `record` output — e.g. `examples/live/recorded-claim-swap-fresh.json` — instead of the fixture. |
| `--out <dir>`               | print to stdout | **`synth` only.** Write `summary.txt`, `spec.json`, `context-rule.json`, and `FrequencyLimitPolicy.rs` into `<dir>` (e.g. `examples/live/fresh`).  |
| `--lifetime <secs>`         | `2592000` (30d) | Context-rule lifetime (sets `valid_until` = synth time + this). |
| `--spend-window <secs>`     | `86400` (1d)    | Rolling window the spend cap is measured over.                  |
| `--cap-multiplier <number>` | `1.1`           | Cap = observed gross outflow × this (rounded up).               |
| `--frequency-window <secs>` | `86400` (1d)    | Rolling window for the frequency limit.                         |
| `--frequency-max <count>`   | `5`             | Max calls allowed within the frequency window.                  |
| `--constrain-arguments`     | off             | Enforce the derived argument constraints (swap-path token set): a violating route is denied instead of flagged. |
| `--probe-token <C…>`        | network native XLM SAC | **`simulate` only.** The token the unobserved-route scenario routes through. Defaults to the recording network's native XLM Stellar Asset Contract; a synthetic placeholder if XLM itself was observed. |

```bash
npm run cli -- synth --lifetime 604800 --cap-multiplier 1.25
npm run cli -- simulate --input examples/live/recorded-claim-swap-fresh.json
npm run cli -- simulate --input examples/live/recorded-claim-swap-fresh.json --constrain-arguments
```

## Install targets (`synth`)

Deploy-time facts the artifact must carry to install as-is
([schema v2](https://github.com/kunal-drall/policywright/blob/main/docs/context-rule-schema.md)):

| Flag                                         | Meaning                                                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--signer delegated:<G…\|C…>`                 | A rule signer in the real OZ `Signer` shape (repeatable, ≤ 15). `external:<verifier C…>:<hex>` for an `External` signer. |
| `--policy-address <kind>=<C…>`               | Deployed policy contract per binding kind: `custom:FrequencyLimitPolicy`, `stock:spending_limit`.                        |
| `--ledger-head <n>`                          | Live ledger head → absolute `validUntilLedger`; omit to emit the relative `lifetimeLedgers` only.                        |

The committed installable artifact's flags are pinned in
[examples/live/fresh/synth.args](https://github.com/kunal-drall/policywright/blob/main/examples/live/fresh/synth.args).

## `record` flags

| Flag                       | Default                       | Meaning                                                                                                                                                                     |
| -------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<txHash> [<txHash> ...]`  | (required unless simulating)  | One or more 64-character hex transaction hashes; a multi-step flow is several hashes (Soroban allows one `InvokeHostFunction` per transaction) merged into one `RecordedTx`. |
| `--account <G...\|C...>`   | first tx's source account     | The subject account movements are attributed to. Without it the fallback is assumed **with a warning** — smart-account flows usually act through a `C...` address.           |
| `--from-simulation <file>` | —                             | Ingest a saved `simulateTransaction` exchange instead of fetching hashes.                                                                                                    |
| `--network <name>`         | `testnet`                     | One of `testnet`, `mainnet`, `futurenet` — the read-only `record` and `verify` accept all three; `install` refuses anything but `testnet` (a mainnet demonstration is a Tranche 3 item, [Roadmap](/roadmap/)). |
| `--rpc-url <url>`          | the network's public endpoint | Override the Soroban RPC endpoint, e.g. a node you run yourself.                                                                                                              |

Default public endpoints per network are defined in
[src/sources/rpc.ts](https://github.com/kunal-drall/policywright/blob/main/src/sources/rpc.ts).

## `install` flags (testnet-only)

The signer is `STELLAR_SECRET_KEY` from the environment — never an argument —
and is never printed; `scripts/install-testnet.sh` sources the gitignored
`.env` for you ([smart-account install](/reference/smart-account-install/)).

| Flag                                | Default                                   | Meaning                                                                                                              |
| ----------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `--artifact <context-rule.json>`    | (required)                                | The emitted artifact, consumed unmodified; refused if it would not install as-is.                                    |
| `--account <C…>`                    | (required)                                | The OpenZeppelin smart account to install into.                                                                      |
| `--admin-rule-id <n>`               | `0`                                       | The account's admin rule (the constructor's).                                                                        |
| `--admin-signer <spec>`             | `delegated:<the signing key's public key>` | The admin rule's signer(s), same syntax as `--signer`.                                                               |
| `--dry-run`                         | off                                       | Simulate everything, including the authorization entries; submit nothing.                                             |
| `--source <G…>`                     | —                                         | Dry-run only: the intended transaction source when `STELLAR_SECRET_KEY` is not set.                                  |
| `--out <install-log.json>`          | —                                         | Write the machine-readable install log.                                                                              |
| `--network <n>`, `--rpc-url <url>`  | `testnet`                                 | `install` is testnet-only: any other network is refused.                                                             |

## `verify` flags

| Flag                                                   | Meaning                                                                                                  |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `--artifact`, `--account`, `--network`, `--rpc-url`    | As above; read-only, no key needed.                                                                      |
| `--install-log <json>`                                 | Compare `valid_until` with what the install computed, and select that install when the same artifact was installed more than once. |
| `--out <verify.md>`                                    | Write the Markdown report.                                                                               |

## Flag syntax and errors

- Flags accept `--key value` or `--key=value`. A boolean flag is true when
  present unless explicitly set to `false`.
- Numeric flags reject non-numeric values with a clear message.
- Every command exits non-zero on error, printing the reason to stderr —
  including RPC failures (not found, failed on-chain, wrong network, malformed
  envelope) and invalid synthesis config.
