## Prerequisites

- Node.js ≥ 22 (declared in
  [package.json `engines`](https://github.com/kunal-drall/policywright/blob/main/package.json))
- npm

## Install

```bash
git clone https://github.com/kunal-drall/policywright.git
cd policywright
npm ci
```

## Run the demo

```bash
npm run demo
```

The demo records the committed fixture, synthesizes the spec, emits the
artefacts to `out/` (`spec.json`, `context-rule.json`, `summary.txt`,
`FrequencyLimitPolicy.rs`, `simulation-report.md`), and runs the six dry-run
scenarios — asserting each behaves as expected. It exits non-zero if any
scenario deviates, so it doubles as a smoke test
([src/demo.ts](https://github.com/kunal-drall/policywright/blob/main/src/demo.ts));
CI runs the same command in every dispatched run
([ci.yml](https://github.com/kunal-drall/policywright/blob/main/.github/workflows/ci.yml),
latest green run [33654658803](https://github.com/kunal-drall/policywright/actions/runs/33654658803)).
`npm test` (215 tests, including the MCP stdio suite and the skill
walkthrough) passed in the same session.

## Synthesize and simulate directly

```bash
# Synthesize a spec from the fixture; print the summary, spec.json, and context-rule.json
npm run cli -- synth

# Synthesize from a saved recording instead of the fixture
npm run cli -- synth --input examples/live/recorded-claim-swap.json

# Run the dry-run scenarios against the fixture's spec
npm run cli -- simulate

# Dry-run the REAL recorded claim→swap sequence, both ways
npm run cli -- simulate --input examples/live/recorded-claim-swap-fresh.json
npm run cli -- simulate --input examples/live/recorded-claim-swap-fresh.json --constrain-arguments

# Override synthesis knobs (anything omitted keeps its default)
npm run cli -- synth --lifetime 604800 --cap-multiplier 1.25
```

All six ran on 2026-09-02. The two `--input …fresh.json` reports were
byte-identical to the committed
[simulation-report.md](https://github.com/kunal-drall/policywright/blob/main/examples/live/simulation-report.md)
and
[simulation-report.constrained.md](https://github.com/kunal-drall/policywright/blob/main/examples/live/simulation-report.constrained.md)

## Record a flow

A multi-step flow (like the Blend claim followed by the Soroswap swap) is
several transaction hashes — Soroban allows one `InvokeHostFunction` per
transaction. Passing every hash merges them into **one** `RecordedTx`, ordered
by ledger close time. `record` decodes the `InvokeContract` calls and
CAP-67/SEP-41 token events, resolves each token's symbol/decimals by
simulating its SEP-41 `symbol()` / `decimals()` getters against the same node
(with an explicit `resolved: false` fallback to the full contract id when that
is not possible), and prints the merged recording as JSON
([src/sources/rpc.ts](https://github.com/kunal-drall/policywright/blob/main/src/sources/rpc.ts)).
No test contacts a live node: the decoders and the multi-hash merge run in
[test/recorder.test.ts](https://github.com/kunal-drall/policywright/blob/main/test/recorder.test.ts)
against the committed raw captures, and the MCP `record` tool is driven
against a local stub RPC in
[test/mcp.test.ts](https://github.com/kunal-drall/policywright/blob/main/test/mcp.test.ts).

```bash
npm run record -- <txHash> [<txHash> ...] [--account <G...|C...>] \
  [--network <name>] [--rpc-url <url>]

# Or ingest a saved simulateTransaction exchange instead of fetching hashes
npm run record -- --from-simulation <file.json> --account <G...|C...>
```

- `--account` names the subject the movements are attributed to. Without it,
  the first transaction's source account is assumed and a warning records the
  assumption — smart-account flows usually act through a `C...` address, not
  the envelope source.
- `--from-simulation` ingests a saved `simulateTransaction` exchange
  (`source: "simulation"`) — simulation discovers the authorization tree an
  unsigned envelope does not carry.
- `--network` defaults to `testnet` (the accepted network names are in the
  [CLI reference](/reference/cli/#record-flags)); `--rpc-url` overrides the
  endpoint, including a node you run yourself.
- Failures return a typed error — `BAD_INPUT` / `TX_NOT_FOUND` / `NETWORK` /
  `DECODE_FAILED` — instead of empty output
  ([src/sources/errors.ts](https://github.com/kunal-drall/policywright/blob/main/src/sources/errors.ts)).

## Drive it from an agent

`npm run mcp` serves the same four operations — `record`, `synthesize`,
`simulate`, `verify` — to an MCP client over stdio. Claude Code picks the
server up from the committed
[`.mcp.json`](https://github.com/kunal-drall/policywright/blob/main/.mcp.json)
when you open the repository root
([src/mcp/server.ts](https://github.com/kunal-drall/policywright/blob/main/src/mcp/server.ts)
registers exactly four tools); checked on 2026-09-02:

```text
$ claude mcp list
Checking MCP server health...

policywright: node node_modules/tsx/dist/cli.mjs src/mcp/server.ts - ✓ Connected
```

There is no install or deploy tool. The [MCP server](/reference/mcp-tools/)
page has the schemas, error codes and registration; [the skill](/reference/skill/)
page has the "grant permission to do X from this transaction" conversation.

## Verify the testnet install — read-only, no key

What is installed on the live testnet smart account can be read back and
diffed against the committed artifact by anyone:

```bash
npm run cli -- verify --artifact examples/live/fresh/context-rule.json \
  --account CBQ6H7ILH54ADWTVS7FCK36W7FY2RJJOWR4VGLZG7D4PZUG5FSA7QHDT \
  --install-log examples/live/testnet/install-20260902T105742Z.json
```

On 2026-09-02 this printed `# policywright verify — PASS` with 15 of 15 rows
`✅` at ledger 4469061; the full output is on the
[smart-account install](/reference/smart-account-install/#the-read-only-verify-anyone-can-run)
page. The rows pass while the installed rules are live (until ledger 4983015,
about 2026-10-02).

## Install into a testnet smart account — human-signed, testnet only

The deploy-second half is an explicit CLI step, never an agent call:
`synth --signer … --policy-address …` emits an artifact that installs as-is,
`install --dry-run` validates and simulates it and submits nothing, `install`
signs client-side with the operator's own testnet key from the gitignored
`.env` and submits, and `verify` reads the rules back. It is **testnet-only**
— the command refuses any other network. Live trail: the testnet account
[`CBQ6H7IL…QHDT`](https://stellar.expert/explorer/testnet/contract/CBQ6H7ILH54ADWTVS7FCK36W7FY2RJJOWR4VGLZG7D4PZUG5FSA7QHDT),
its [install logs and verify outputs](https://github.com/kunal-drall/policywright/tree/main/examples/live/testnet).
Flow, signing hierarchy, and today's dry-run output:
[smart-account install](/reference/smart-account-install/).
