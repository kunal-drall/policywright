Policywright generates artefacts that, once installed, run as authorization
logic over user funds. Security is therefore treated as a first-class
deliverable. This page separates what is **in the code today** (each claim
linked to its source) from what is **planned**.

## Protections in v0

- **No custody of user keys.** Policywright never asks for or holds a user's
  keys, and it does not sign, deploy, or relay **user** transactions. The only
  on-chain action in the repository is the opt-in, **testnet-only** deployment
  of the generated policy contract itself, signed with a gitignored testnet
  identity
  ([scripts/deploy-testnet.sh](https://github.com/kunal-drall/policywright/blob/main/scripts/deploy-testnet.sh);
  the script refuses any network other than testnet).
- **Code-first, deploy-second.** Every output is a file written locally for
  review — `spec.json`, `context-rule.json`, `summary.txt`, the generated
  Rust, and the dry-run report. Nothing installs automatically
  ([src/demo.ts](https://github.com/kunal-drall/policywright/blob/main/src/demo.ts)).
  Installing is a separate, human-initiated CLI step: the artifact is validated
  field-by-field against the OpenZeppelin install signature and refused if it
  would not install as-is, simulated in enforcing mode with the real
  authorization entries before anything is signed, and signed **client-side**
  through a labelled signing surface — the `.env` key fallback today, a wallet
  signing the same transaction as the open primary track. The signing mode and
  its reason are printed in every output and install log; the secret is read
  from the environment only and never logged
  ([docs/smart-account-install.md](https://github.com/kunal-drall/policywright/blob/main/docs/smart-account-install.md)).
- **Deny-case verification.** The dry-run harness auto-generates adjacent
  scenarios that must fail — over the spend cap, an unseen function, after
  expiry, over the frequency cap — plus the recorded swap re-routed through an
  unobserved token (BLND→XLM on the real testnet recording), which is denied
  when argument constraints (`--constrain-arguments`) are enabled and
  advisory-flagged (permitted, with the gap named) otherwise. The demo asserts
  every scenario behaves as expected, exiting non-zero otherwise
  ([src/simulate.ts](https://github.com/kunal-drall/policywright/blob/main/src/simulate.ts)).
- **Real shapes only, deltas declared.** The installable `context-rule.json`
  targets a pinned OZ release (`stellar-accounts` v0.7.2) using its real
  parameter names and units, with an OZ `file:line` citation on every policy
  binding; anything the stock policies cannot express is recorded as an
  explicit composition-delta note rather than emitted in a shape the real
  contract would reject
  ([docs/context-rule-schema.md](https://github.com/kunal-drall/policywright/blob/main/docs/context-rule-schema.md)).
- **Unaudited output is stamped as such.** Every generated Rust file carries an
  `ILLUSTRATIVE / UNAUDITED — NOT DEPLOY-READY` header — including, verbatim,
  the banner sentence at the top of this page — with a source comment
  instructing that the wording never be weakened
  ([src/rust-policy.ts](https://github.com/kunal-drall/policywright/blob/main/src/rust-policy.ts)).
- **The generated policy is compiled and tested, not just rendered.** The
  emitted source is byte-identical (at the default config) to the crate at
  [contracts/frequency-limit-policy](https://github.com/kunal-drall/policywright/tree/main/contracts/frequency-limit-policy),
  which implements the real OZ `Policy` trait and passes 25 Rust tests;
  equality between the emitter template and the crate source is locked by
  [test/rust-policy.test.ts](https://github.com/kunal-drall/policywright/blob/main/test/rust-policy.test.ts).
- **Reproducible build, hash-verified deployment.** Two clean local builds and
  the CI build on a different OS/architecture produce the **identical** wasm
  SHA-256, and CI asserts that equality on every run
  ([docs/FACTS.md §1.5](https://github.com/kunal-drall/policywright/blob/main/docs/FACTS.md)).
  The testnet instance was deployed by a script that re-fetches the on-chain
  wasm and verifies its hash equals the local build — contract ID, transaction
  links, and the full deployment log are in
  [evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md).
  The deployed instance is testnet-only and unaudited.
- **Storage segregation.** The generated policy follows the stock-policy
  storage pattern: all state keyed by
  `AccountContext(smart_account, context_rule_id)` in persistent storage, so
  state cannot bleed across accounts or rules — the same pattern every stock
  OZ policy uses
  ([docs/FACTS.md §2.4](https://github.com/kunal-drall/policywright/blob/main/docs/FACTS.md)).
- **Defensive input handling.** The fixture loader validates every field and
  fails with a precise `FixtureError`; the recording layer returns typed
  errors — `BAD_INPUT` / `TX_NOT_FOUND` / `NETWORK` / `DECODE_FAILED` — for
  not-found, failed-on-chain, wrong-network, and malformed-envelope cases;
  synthesis config is validated up front
  ([src/sources/errors.ts](https://github.com/kunal-drall/policywright/blob/main/src/sources/errors.ts),
  [src/synthesizer.ts](https://github.com/kunal-drall/policywright/blob/main/src/synthesizer.ts)).
- **Deterministic money math.** Token amounts are `bigint` end to end — no
  float rounding — and synthesis takes the clock as an explicit parameter, so
  results are reproducible and testable. The synthesizer and simulator are held
  to ≥90% line-coverage thresholds via `npm run test:coverage`
  ([vitest.config.ts](https://github.com/kunal-drall/policywright/blob/main/vitest.config.ts)).

## Threat model

The categories below frame both v0's existing mitigations and the scope of the
planned audit. In each row, the middle column describes only what exists in the
repository today; the audit work is planned.

| Threat                                    | v0 mitigation (in the code today)                                                                                             | Planned audit focus                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| Malicious or malformed input transactions | Defensive fixture validation; strict envelope/event narrowing with typed errors; decoders tested against committed real captures | Adversarial input corpus against the synthesizer     |
| Over-broad scope inference                | Exact `(contract, fn)` binding; gross-outflow caps; no cap only for inflow-only assets; advisory flags for gaps                | Systematic review of every inference rule            |
| Storage collisions across accounts/rules  | Generated policy keys state by `AccountContext(smart_account, context_rule_id)`, tested in the crate's Rust suite              | Verification of the generated storage patterns       |
| Policy bypass                             | Fixed-order dry-run checks with auto-generated deny cases asserted by the demo and tests                                       | Bypass hunting on synthesizer output and templates   |
| Incorrect lifecycle handling              | Generated code implements the real OZ `Policy` trait and passes 25 Rust tests against `stellar-accounts` v0.7.2               | Conformance review against the OZ accounts lifecycle |
| Install-shape drift                       | `context-rule.json` pins the OZ release and cites every param shape to source; deltas are named notes, not invalid shapes      | Review of the install mapping end to end             |

## Audit commitment

The audit commitment is: **a third-party audit of the synthesizer logic itself
and the generated policy templates, via the SCF Audit Bank at Tranche 3.**

That audit is a Tranche 3 target and has not happened. Until it has, every
generated contract remains stamped illustrative and unaudited, deployment stays
testnet-only, and this site carries the banner above on every page that shows
generated Rust. See the [Roadmap](/roadmap/) for the tranche plan.
