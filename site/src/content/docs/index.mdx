Policywright turns a transaction a user has already performed (or simulated) on
Stellar/Soroban into the **least-privilege
[OpenZeppelin smart-account](https://docs.openzeppelin.com/stellar-contracts/accounts/smart-account)
authorization** that permits exactly that flow — context rules plus the minimum
set of policies — and lets them verify it with a dry-run before anything is
installed on-chain.

The project is **in development**, built for Stellar SCF #44 as the awarded
submission
["Record-to-Policy MCP + Agent skill"](https://communityfund.stellar.org/project/policywright-j8x),
against a three-tranche plan (see the [Roadmap](/roadmap/)). This site
documents version 0 (`0.1.0` in
[package.json](https://github.com/kunal-drall/policywright/blob/main/package.json)),
an offline-first pipeline you can run today.

## The pipeline

1. **Record** — capture a flow as a normalised `RecordedTx`: the scoped
   contract calls and the token in/out flows. Sourced from a committed offline
   fixture, from a live Soroban RPC node (one or more transaction hashes,
   merged in ledger-close-time order), or from a saved `simulateTransaction`
   exchange.
2. **Synthesize** — derive a least-privilege `SmartAccountSpec`: scope bound to
   the exact `(contract, function)` pairs observed, a gross-outflow spending
   cap per asset that left the account, no cap for assets that only flowed in,
   and an always-on frequency limit.
3. **Emit** — render the spec as machine-readable JSON, a human-readable
   summary, an _illustrative_ custom Rust policy, and `context-rule.json`: the
   installable OpenZeppelin context rules, with the stock `spending_limit`
   attached under its real install params where the recording supports it
   ([schema](https://github.com/kunal-drall/policywright/blob/main/docs/context-rule-schema.md)).
4. **Simulate** — dry-run candidate calls against the spec and report whether
   each would be permitted, denied, or flagged — and why — before anything is
   installed.

See [Architecture](/architecture/) for the design in depth, and
[Getting Started](/getting-started/) to run it.

## What exists in v0

Everything below is in the repository today; the demo and tests run offline:

- **Recording layer** — offline fixture loader; a live Soroban RPC adapter
  that fetches one or more transactions by hash and merges them into a single
  `RecordedTx` (CAP-67/SEP-41 token events, SAC metadata resolution, explicit
  `--account` subject); and a simulated path that ingests a saved
  `simulateTransaction` exchange. The decoders are tested network-free against
  committed raw captures of real testnet transactions —
  [src/sources/](https://github.com/kunal-drall/policywright/tree/main/src/sources),
  [examples/live/](https://github.com/kunal-drall/policywright/tree/main/examples/live),
  [test/recorder.test.ts](https://github.com/kunal-drall/policywright/blob/main/test/recorder.test.ts)
- **Least-privilege synthesizer** — scope binding, gross-outflow spend caps,
  minimal-permission inflow handling, frequency limits, and config-gated
  argument-level scope —
  [src/synthesizer.ts](https://github.com/kunal-drall/policywright/blob/main/src/synthesizer.ts)
- **Emitter** — `spec.json`, `context-rule.json` (installable OZ context rules
  with real stock-policy install params and explicit composition-delta notes),
  `summary.txt`, and a clearly-stamped illustrative Rust policy —
  [src/emitter.ts](https://github.com/kunal-drall/policywright/blob/main/src/emitter.ts),
  [docs/context-rule-schema.md](https://github.com/kunal-drall/policywright/blob/main/docs/context-rule-schema.md)
- **Compiled, tested, testnet-deployed generated policy** — the emitted Rust
  is byte-identical to the crate at
  [contracts/frequency-limit-policy](https://github.com/kunal-drall/policywright/tree/main/contracts/frequency-limit-policy),
  which compiles against the real OZ `Policy` trait (`stellar-accounts`
  v0.7.2), passes 25 Rust tests, builds to a reproducible wasm, and has a
  hash-verified instance deployed on testnet — deployment log and contract ID
  in
  [evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md)
- **Dry-run simulator** — permit/deny/flag evaluation with auto-generated deny
  cases —
  [src/simulate.ts](https://github.com/kunal-drall/policywright/blob/main/src/simulate.ts)
- **CLI, tests, and CI** — `demo`, `synth`, `simulate`, and `record` commands;
  a Vitest suite (90 tests) with coverage thresholds; CI with three jobs
  (build, docs site, contracts) configured for pushes to `main` and pull
  requests, with runs cited per deliverable in the evidence pack —
  [src/cli.ts](https://github.com/kunal-drall/policywright/blob/main/src/cli.ts),
  [CI workflow](https://github.com/kunal-drall/policywright/actions/workflows/ci.yml)

v0 does **not** sign, deploy, or relay user transactions — the only on-chain
action in the repository is the opt-in, testnet-only deployment of the
generated policy contract itself
([scripts/deploy-testnet.sh](https://github.com/kunal-drall/policywright/blob/main/scripts/deploy-testnet.sh)).
There is no MCP server, Claude skill, or wallet integration yet; those are
planned — see the [Roadmap](/roadmap/).

## The worked example and its assets

The worked example throughout this site is a Stellar/Soroban flow: a **Blend**
pool emissions claim (BLND in) followed by a **Soroswap** exact-input swap of
that BLND into **USDC** (BLND out, USDC in).

Two kinds of recordings appear in the repository, and they are labelled
honestly:

- The **deterministic test fixture** uses labelled synthetic assets —
  well-formed but synthetic contract addresses carrying the symbols BLND, XLM,
  and USDC (the
  [fixture](https://github.com/kunal-drall/policywright/blob/main/fixtures/recorded-tx.json)
  says so in its own note) — and is never presented as real USDC.
- The **committed live captures** under
  [examples/live/](https://github.com/kunal-drall/policywright/tree/main/examples/live)
  are real **testnet** transactions. Their BLND and USDC are the Blend/Soroswap
  _testnet_ mints, with contract IDs pinned and source-cited in
  [docs/FACTS.md](https://github.com/kunal-drall/policywright/blob/main/docs/FACTS.md)
  (GATE 4) — test assets, not Circle-issued USDC.

Mainnet demonstrations are planned for Tranche 3 and do not exist yet. When
they are published, they will use the Circle-issued USDC asset on Stellar,
with the issuer pinned in config and verified against Circle's official
documentation.

## Prior art

Policywright extends the prior art of
[kalepail/pollywallet](https://github.com/kalepail/pollywallet) by Tyler van der
Hoeven — a passkey-secured smart-wallet demo on Stellar that deploys
OpenZeppelin smart-account contracts on Soroban. pollywallet shows how to create
and operate a smart wallet; Policywright adds the step of deriving the
least-privilege authorization from a transaction the user already performed,
plus an offline dry-run to verify it before installing. See the
[README acknowledgements](https://github.com/kunal-drall/policywright#acknowledgements)
for the full adopt/extend/replace breakdown.
