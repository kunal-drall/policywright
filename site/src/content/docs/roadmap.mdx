Policywright is built against a three-tranche plan — **MVP → Testnet →
Mainnet** — tracking the funded deliverables of the awarded SCF #44 submission
["Record-to-Policy MCP + Agent skill"](https://communityfund.stellar.org/project/policywright-j8x).
All dates are **targets**. Deliverables that involve on-chain behaviour are
evidenced by contract IDs and transaction links when they exist; the first —
the deployed generated frequency-limit policy — is evidenced in the deployment
log in
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md).

## The three tranches

| Tranche                  | Target date                | Focus              | Headline deliverables                                                                                                                                                                                       |
| ------------------------ | -------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **T1 — MVP (testnet)**   | 31 Aug 2026 _(target)_     | Working engine     | Recording layer (live + simulated); least-privilege synthesizer (scope + composed policies + minimal permission); generated-policy compile + testnet deploy; open-source CLI + CI                             |
| **T2 — Testnet expansion** | 15 Oct 2026 _(target)_   | Agent-usable tooling | MCP server (`record` / `synthesize` / `simulate` / `verify` tools); Claude skill; dry-run harness + argument-level scope; net-new policy codegen with storage segregation; wallet integration (testnet, end-to-end) |
| **T3 — Mainnet launch**  | 30 Nov 2026 _(target)_     | Production         | Three documented end-to-end walkthroughs; OpenZeppelin validation of generated code; production release (versioned MCP server + packaged skill + docs); mainnet demonstration; test suite + audit readiness (audit scope submitted to the SCF Audit Bank) |

## Where the project stands

Tranche 1 (D1.1–D1.4) is delivered; Tranche 2 is in progress, with D2.3 (the
dry-run harness with supported argument-level scope), D2.4 (composed
configuration + generated stateful policy, both compiling and passing
simulation), D2.5 (a testnet OpenZeppelin smart account with the emitted
rules installed as-is and verified on-chain — fallback signing path; the
cohort-wallet track stays open) and D2.1 (the MCP server: `record` /
`synthesize` / `simulate` / `verify` over stdio, no install/deploy tool,
driven end to end by a network-free test suite) delivered on 2026-09-02. Each
item below is verifiable today:

- Recording from the offline fixture and from a live Soroban RPC node by
  transaction hash —
  [src/sources/](https://github.com/kunal-drall/policywright/tree/main/src/sources)
- The least-privilege synthesizer: exact scope binding, gross-outflow spend
  caps, the minimal-permission inflow rule, and frequency limits —
  [src/synthesizer.ts](https://github.com/kunal-drall/policywright/blob/main/src/synthesizer.ts)
- The emitter: `spec.json`, `context-rule.json`, `summary.txt`, and the stamped
  illustrative Rust policy — the same source as the compiled-and-tested crate at
  [contracts/frequency-limit-policy](https://github.com/kunal-drall/policywright/tree/main/contracts/frequency-limit-policy) —
  [src/emitter.ts](https://github.com/kunal-drall/policywright/blob/main/src/emitter.ts)
- The dry-run harness: permit / deny / flag reports with auto-generated deny
  cases and argument-level scope (derived always, enforced with
  `--constrain-arguments`), proven both ways on the real recorded claim→swap
  sequence — BLND→XLM flagged by default, denied when enabled
  ([committed reports](https://github.com/kunal-drall/policywright/tree/main/examples/live),
  [src/simulate.ts](https://github.com/kunal-drall/policywright/blob/main/src/simulate.ts))
- The open-source CLI, Vitest suite with coverage thresholds, and CI running
  lint → format → typecheck → test → demo —
  [src/cli.ts](https://github.com/kunal-drall/policywright/blob/main/src/cli.ts),
  [CI workflow](https://github.com/kunal-drall/policywright/actions/workflows/ci.yml)
- The MCP server — four tools over stdio, versioned schemas, typed error
  codes, Claude Code registration from the committed `.mcp.json` —
  [reference](/reference/mcp-tools/),
  [src/mcp/](https://github.com/kunal-drall/policywright/tree/main/src/mcp)

Beyond that list, the simulated-transaction recording path shipped with D1.1,
and the generated policy compiles, passes its Rust test suite, and is deployed
to testnet (hash-verified) since D1.3 — deployment log in
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md).
- A live testnet smart account (OpenZeppelin's example account, built from
  pinned source) with the synthesised rules installed **as-is** from the
  committed artifact and read back on-chain to a PASS —
  [examples/live/testnet/](https://github.com/kunal-drall/policywright/tree/main/examples/live/testnet),
  [docs/smart-account-install.md](https://github.com/kunal-drall/policywright/blob/main/docs/smart-account-install.md)

The T2 deliverables D2.1 and D2.3–D2.5 are evidenced in
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md).

The remaining items are planned and have not been started in this repository:
the Claude skill, the wallet (Freighter) signing page, the walkthroughs, the
OpenZeppelin validation pass, the mainnet demonstration, and the Audit Bank
submission
([docs/T2-NOTES.md](https://github.com/kunal-drall/policywright/blob/main/docs/T2-NOTES.md)).
The human-recorded MCP reference session and demo recordings are the open
blockers listed in
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md).
