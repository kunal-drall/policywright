Policywright is built against a three-tranche plan — **MVP → Testnet →
Mainnet** — tracking the funded deliverables of the awarded SCF #44 submission
["Record-to-Policy MCP + Agent skill"](https://communityfund.stellar.org/project/policywright-j8x).
All dates are **targets**. Deliverables that involve on-chain behaviour are
evidenced by contract IDs and transaction links when they exist; the first —
the deployed generated frequency-limit policy — is evidenced in the deployment
log in
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md),
and the Tranche 2 table below links each deliverable's evidence section.

## The three tranches

| Tranche                  | Target date                | Focus              | Headline deliverables                                                                                                                                                                                       |
| ------------------------ | -------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **T1 — MVP (testnet)**   | 31 Aug 2026 _(target)_     | Working engine     | Recording layer (live + simulated); least-privilege synthesizer (scope + composed policies + minimal permission); generated-policy compile + testnet deploy; open-source CLI + CI                             |
| **T2 — Testnet expansion** | 15 Oct 2026 _(target)_   | Agent-usable tooling | MCP server (`record` / `synthesize` / `simulate` / `verify` tools); Claude skill; dry-run harness + argument-level scope; net-new policy codegen with storage segregation; wallet integration (testnet, end-to-end) |
| **T3 — Mainnet launch**  | 30 Nov 2026 _(target)_     | Production         | Three documented end-to-end walkthroughs; OpenZeppelin validation of generated code; production release (versioned MCP server + packaged skill + docs); mainnet demonstration; test suite + audit readiness (audit scope submitted to the SCF Audit Bank) |

## Where the project stands

Tranche 1 (D1.1–D1.4) is delivered and approved. The five Tranche 2
deliverables are built and evidenced as of 2026-09-02; what is still open in
each is a human recording. Every row links to the section of
[evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md)
that quotes the approved criterion verbatim and gives the verification
commands.

**Not built in Tranche 2, stated plainly:** the wallet signing page (it
replaces only the installer's signing surface — the `Delegated(G)` model is
proven with the local key as `G`), an on-chain argument-scoping policy (the
harness enforces argument scope offline; not an approved T2 criterion), and
the optional post-install enforcement demo. Each is tracked in
[docs/T2-NOTES.md](https://github.com/kunal-drall/policywright/blob/main/docs/T2-NOTES.md).

### Tranche 1 (delivered 2026-08-03)

- Recording from the offline fixture, from a live Soroban RPC node by
  transaction hash, and from a saved `simulateTransaction` exchange —
  [src/sources/](https://github.com/kunal-drall/policywright/tree/main/src/sources)
- The least-privilege synthesizer: exact scope binding, gross-outflow spend
  caps, the minimal-permission inflow rule, and frequency limits —
  [src/synthesizer.ts](https://github.com/kunal-drall/policywright/blob/main/src/synthesizer.ts)
- The emitter: `spec.json`, `context-rule.json`, `summary.txt`, and the stamped
  illustrative Rust policy — the same source as the compiled-and-tested crate at
  [contracts/frequency-limit-policy](https://github.com/kunal-drall/policywright/tree/main/contracts/frequency-limit-policy),
  deployed to testnet hash-verified — deployment log in
  [evidence/EVIDENCE.md](https://github.com/kunal-drall/policywright/blob/main/evidence/EVIDENCE.md)
- The open-source CLI, Vitest suite with coverage thresholds, and CI —
  [src/cli.ts](https://github.com/kunal-drall/policywright/blob/main/src/cli.ts),
  [CI workflow](https://github.com/kunal-drall/policywright/actions/workflows/ci.yml)

### Planned — Tranche 3 (not started)

The three documented end-to-end walkthroughs, the OpenZeppelin validation
pass of the generated code, the production release (versioned MCP server,
packaged skill, docs), the mainnet demonstration, and the audit-readiness
work with the SCF Audit Bank. Nothing under this heading exists in the
repository; ideas that surface early are parked in
[docs/T3-NOTES.md](https://github.com/kunal-drall/policywright/blob/main/docs/T3-NOTES.md).
